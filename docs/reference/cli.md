# `om` CLI reference

`bin/om` is the single engine entrypoint. Hook subcommands read the Claude Code hook payload JSON on stdin (`om finalize` takes arguments instead). Manual subcommands run as `om <cmd>` in the session's Bash tool (the plugin's `bin/` is on its PATH) or as `bin/om <cmd>` elsewhere.

## Hook subcommands

| Subcommand | Called by | Effect | Output |
|---|---|---|---|
| `om session-start` | `SessionStart` hook | On `fork`, seeds a missing watermark at the transcript head. Builds the memory block from pinned facts, journey tail, `MEMORY.md` head, and the recent ledger; checks that native auto memory is disabled ([`CLAUDE_CODE_DISABLE_AUTO_MEMORY`](configuration.md#related-claude-code-settings); then, under the project root ([memory directory](file-layout.md#durable-memory-directory)), `.claude/settings.local.json` and `.claude/settings.json`, then `${CLAUDE_CONFIG_DIR:-~/.claude}/settings.json`) | `additionalContext` JSON (omitted if every section is empty); `systemMessage` warning if auto memory is not disabled |
| `om user-prompt` | `UserPromptSubmit` hook | Takes the first 15 unique prompt words (sorted) matching `[A-Za-z_][A-Za-z_-]{4,}`, greps them case-insensitively over topic `*.md` files (excluding `MEMORY.md`, `JOURNEY.md`, `pinned-facts.md`), and ranks files by hit count | `additionalContext` hint listing up to `OM_RETRIEVE_MAX_FILES` files, or nothing |
| `om observe` | `PostToolUse` hook (async) | When ≥ `OM_CHUNK_BYTES` of newline-terminated transcript lines lie past the watermark: extracts a line-aligned chunk, runs the observer model (`claude -p --model OM_OBSERVER_MODEL --tools "" --no-session-persistence` with `OM_NESTED=1` and auto memory disabled, from the data root, capped at 600 s), and on any non-empty reply advances the watermark (a chunk of blank lines only advances it past them without an observer run): `- ` lines are appended to the ledger, `(no observations)` appends nothing, any other reply without `- ` lines is logged to `observe.log`. Lock-guarded; on observer failure (including the cap: exit 124, or 137 after the 10 s kill grace) the watermark is kept. After appending, triggers detached consolidation when the ledger has ≥ `OM_LEDGER_SOFT_LIMIT` lines, unless a consolidation of this memory directory failed recently ([work directory](file-layout.md#consolidator-work-directory)). `--flush` (internal) processes a tail ≥ `OM_FLUSH_MIN_BYTES` | none |
| `om pre-compact` | `PreCompact` hook | Snapshots the ledger, then synchronously drains the observer backlog before compaction proceeds: flush passes block on the observe lock and repeat until the watermark reaches the transcript head, a pass makes no progress, or a 60-pass cap; records the trigger and drain result in `events.log` | none |
| `om session-end` | `SessionEnd` hook | Records the event in `events.log` and detaches `om finalize` | none |
| `om finalize` | detached by `session-end` as `om finalize --session <id> --cwd <dir> --transcript <path>` | Drains the transcript through the observer (the `pre-compact` loop; [`OM_NO_SPAWN`](configuration.md#environment-variables-read-by-binom)), removes stale session state directories ([file layout](file-layout.md#session-state-data-rootsessionssession_id)), then consolidates the whole ledger (`--all`) if it has ≥ `OM_FINALIZE_MIN_LINES` lines, and services [`needs-finalize`](file-layout.md#session-state-data-rootsessionssession_id) markers left by other sessions of the same memory directory; a signal to `om finalize` is passed to the running consolidation and ends `finalize` | `finalize.log` in the session directory |

## Manual subcommands

| Subcommand | Arguments | Effect |
|---|---|---|
| `om status` | — | Prints `memory dir : <dir>`, `data root  : <root>`, `auto memory: disabled (cc-om owns the memory dir)` or `auto memory: ENABLED — ...`, `memory files:` with one entry per line (or `  (none)` if the directory does not exist), and `sessions (this project):` with, per session, `  <id> ledger=<n>/<OM_LEDGER_SOFT_LIMIT> lines, watermark=<w> transcript lines`, then `    last observer issue: <last observe.log line>` (only if `observe.log` is non-empty and `watermark.lines` is missing or not newer than it) and `    consolidation pending (needs-finalize)` while the session's [`needs-finalize`](file-layout.md#session-state-data-rootsessionssession_id) marker exists |
| `om remember` | `"<fact>"` | Appends the fact, newlines and carriage returns replaced by spaces, as a `(pinned)`-marked bullet to `pinned-facts.md` (adding a missing final newline first) and prints `om: pinned to <path>`; waits for a running consolidation of the same memory directory first (`om: waiting for a running consolidation to finish` on stderr) |
| `om consolidate` | `[--session <id>] [--cwd <dir>] [--all]` | Promotes ledger overflow (whole `### ` blocks, leaving at least the last `OM_RECENT_OBS_LINES` lines; with `--all`, the whole ledger) into topic files via the consolidator model, then trims the ledger. Serialized per memory directory (a second run prints `om: consolidation already running for <memory directory>` and exits 0, or blocks when `OM_LOCK_WAIT` is set and exits 1 if the wait runs out); works from a snapshot of the ledger. The consolidator model runs as `claude -p` in a copy of the memory directory with `--allowedTools Read,Write,Edit,Glob,Grep`, `--permission-mode acceptEdits`, `--no-session-persistence`, `OM_NESTED=1`, and `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`, capped at 1800 s; the [work directory](file-layout.md#consolidator-work-directory) is reset, and `.<name>.om-tmp` leftovers in the memory directory (any depth) are removed; `*.md` files whose content it changed or created (at any depth) are staged as `.<name>.om-tmp` beside their target in the memory directory and, once all are staged, renamed into place; a failure while staging removes the staged files (a subdirectory created for them stays) and leaves the memory directory's files unchanged; a failure while renaming leaves the files already renamed in place and removes the rest (both reported as `copy-back failed for <file>`). If the `*.md` content-hash manifest of the copy is unchanged, or changed only by removals, the run fails with `consolidator wrote nothing`. A failed run keeps the ledger intact. The ledger snapshot and the trim each take the session's observe lock ([`OM_LOCK_WAIT`](configuration.md#environment-variables-read-by-binom); if it stays busy, the run is skipped with exit 1, or the ledger is left untrimmed with a warning). Defaults: the session of this project with the largest ledger (newest on ties), reported as `om: session <id>`; current directory; with `--session`, the session's recorded memory directory is used |

## Exit behavior

- Hook subcommands exit 0 in all normal cases, including "nothing to do".
- `consolidate` exits 0 with `om: consolidated into <memory directory>` on success, `om: nothing to consolidate` when no whole block can be promoted, or, without `OM_LOCK_WAIT`, `om: consolidation already running for <memory directory>`. It exits non-zero when the ledger is empty, no session of this project has a ledger, the `claude` CLI is missing, a lock wait runs out, the run is interrupted, or the run fails; a failed run reports `om: <reason>; ledger kept; work dir kept at <work dir>-failed` (without the last clause when the work dir is gone) with reason `consolidator exited <n>` (`124` or `137`: the cap), `consolidator wrote nothing`, `work dir missing after run`, or `copy-back failed for <file>` ([file layout](file-layout.md#consolidator-work-directory)), and leaves the ledger intact. An interrupt, hangup, or termination signal to `om` sends SIGTERM to the running model call and everything it spawned, and the run reports `om: consolidator interrupted; ledger kept` with no `-failed` work directory (so no backoff).
- `remember` exits non-zero (`om: remember: consolidation lock busy`) when the consolidation lock stays busy for its whole wait ([configuration](configuration.md)), or with a usage message when the fact is missing or blank. Unknown arguments to `consolidate` or `finalize` exit non-zero.
- `jq`, `flock`, `setsid`, `md5sum`, or `timeout` missing is fatal at startup, as is an invalid `OM_*` value ([configuration](configuration.md#environment-variables-read-by-binom)). A missing `claude` CLI makes observer runs fail (logged to `observe.log`, watermark kept) and consolidation runs fail (ledger kept; logged to `consolidate.log` mid-session, `finalize.log` at session end, stderr for manual runs).
